# 요구사항 명세

## 1. 개요

### 1.1 목적

지하철에서 물건을 분실한 사용자가 습득물 정보를 빠르게 조회하고, 아직 등록되지 않은 경우 조건을 등록해두면 매칭되는 습득물이 등록되었을 때 이메일로 알림을 받을 수 있는 서비스를 제공한다.

### 1.2 배경

국가 분실물 포털은 교통수단 구분 없이 통합 검색만 제공하여, 지하철 이용자가 필요한 정보를 찾기 어렵다. 또한 분실 시점에 습득물이 아직 등록되지 않은 경우가 많아, 사용자가 반복적으로 재검색해야 하는 불편이 있다.

### 1.3 범위

- 지하철 습득물에 한정한다. 버스·택시 등 타 교통수단은 범위에서 제외한다.
- 지하철 습득물은 보관장소가 지하철역 또는 역사 내 유실물센터인 습득물로 정의한다.
- 데이터 출처는 경찰청 공공 API로 한정한다.
- 정보 조회와 알림까지를 범위로 한다.

## 4. MVP 범위

### 4.1 핵심 가치

지하철에서 물건을 분실한 사람이 습득물이 아직 등록되지 않아 반복해서 재검색해야 하는 불편을, 조건 등록 후 매칭 시 이메일로 알려주는 기능으로 줄인다.

### 4.2 기능 후보 분류

| 기능 후보 | 분류 | 근거 |
|---|---|---|
| 지하철 습득물 검색 (역·물품명) | In-scope | 습득물 조회를 통해 원하는 물품이 있는지 확인 가능해야 함 |
| 습득물 상세 조회 | In-scope | 보관 장소를 알아야 실제로 찾으러 갈 수 있음 |
| 알림 조건 등록 (역·물품명·이메일) | In-scope | 매번 조회하지 않고 알림으로 확인 가능하게 할 수 있음 |
| 주기적 데이터 수집·적재 | In-scope | 신규 여부를 판단하려면 이전 데이터가 있어야 함 |
| 매칭 시 이메일 발송 | In-scope | 메일 형태로 알림 전송 |
| 중복 발송 방지 | In-scope | 같은 건으로 매일 메일이 가면 서비스가 아니라 스팸이 됨 |
| 알림 조건 관리·해지 | In-scope | 민감한 개인정보이기 때문에 해지 수단은 필수 |
| 회원가입·로그인 | Out-of-scope | 오로지 알림을 위해서 회원가입하는 것은 불필요 |
| 분실물 신고 | Out-of-scope | 본 서비스는 습득물 데이터만 다룸. 신고 접수와 비슷한 알림 형태로 대체 |
| 버스·택시 등 타 교통수단 | Out-of-scope | 지하철 특화가 본 서비스의 정체성. 추후 업데이트 가능성 있음 |
| 관리자 페이지 | Out-of-scope | 1인 운영이므로 DB 직접 조회로 충분함 |
| 습득물 이미지 자체 저장 | Out-of-scope | 외부 URL 참조로 충분함 |
